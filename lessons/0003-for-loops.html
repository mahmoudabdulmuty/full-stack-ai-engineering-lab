Lesson 0003 — For Loops

Module 2, Lesson 2. One win: replace N manual lines with one loop that runs the drill for every player on the sheet.

In M2L1 you completed tasks one at a time: tasks[0], then [1], then [2] — one line per task. That's a coach reading every name on the team sheet by hand. A for loop is the coach calling the whole sheet in one breath.

1 · The payoff — three lines become one

for task in tasks:
    print_llm_response(f"Please complete this task: {task}")

Reads like English: for each task in tasks, print the LLM response for that task. Shorter than forEach — no callback, no braces, no arrow.

2 · Anatomy

for task in tasks:      # for | loop variable | in | list | colon
    print(task)           # 4-space indent = "this repeats"
task is a name you choose, like a parameter. The : ends the header; the 4-space indent marks the body. Forget the colon → SyntaxError. Uneven indent → IndentationError.

3 · The loop variable is a VALUE — and it outlives the loop

for flavor in flavors:
    print(flavor)         # the value, not the index — no C-style for here

First pass flavor == flavors[0], last pass the final element. After the loop, flavor still exists holding the last value — Python has no block scope, unlike JS const in for-of. The variable is ordinary, like any name from Module 1.

4 · The indentation trap

for flavor in flavors:
    prompt = f"Write a captivating description for {flavor}"
    print_llm_response(prompt)      # indented: runs every pass

Un-indent that last line and it runs once, after the loop, holding the last prompt. No error — silently the wrong thing. Indentation is membership.

5 · The accumulator — build a list with a loop

promotional_descriptions = []           # empty squad
for flavor in ice_cream_flavors:
    prompt = f"Write a captivating description for {flavor}"   # the question
    response = get_llm_response(prompt)  # the ANSWER
    promotional_descriptions.append(response)                  # store the answer

Start empty, append each result. After the loop, len() equals len() of the source — measure, don't guess. Storing the prompt instead of the response runs clean and is silently wrong.

Check yourself

tasks has 3 items. How many times does the body of for task in tasks: run?

The loop walks the whole list — one pass per item. 3 items, 3 passes, regardless of what the body does.

With 100 items in tasks, what does task equal on the last pass?

Zero-based: 100 items occupy seats 0–99. The variable holds the value at that seat, not the index number itself.

After the loop finishes, what is task?

Python has no block scope. The variable is ordinary and keeps its last binding — unlike JS const task in a for-of, which is scoped to the braces.

If print_llm_response(prompt) is not indented (flush with the for), what happens?

Only indented lines are inside the loop. Un-indented code runs once, afterwards — and prompt still holds the last value. No error, just wrong.

What should promotional_descriptions.append(...) store?

The list is named descriptions — it must hold the LLM's generated answers, not the questions you sent it.

Write the accumulator: a loop over ice_cream_flavors that builds a prompt, gets the response, and appends it to promotional_descriptions (already an empty list).

Key points:
  • for flavor in ice_cream_flavors: — colon and indent
  • build prompt with an f-string wrapping the flavor
  • response = get_llm_response(prompt) — the answer
  • promotional_descriptions.append(response) — store the answer
