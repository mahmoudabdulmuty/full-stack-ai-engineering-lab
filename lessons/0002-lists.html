Lesson 0002 — Lists

Module 2, Lesson 1. One win: store a task list, hand it to the LLM — and predict exactly when it explodes.

In Module 1, writing poems for 3 friends meant 3 identical blocks of code. A list is one variable holding many values — the team-sheet instead of calling each player's name.

1 · Create and read

squad = ["Tommy", "Isabel", "Daniel"]
len(squad)                # 3 — same len() that counts string characters
type(squad)               # <class 'list'>
squad[0]                  # 'Tommy'  — zero-based, square brackets only
squad[3]                  # IndexError: list index out of range
Indexing uses [], never (). Asking for seat 3 on a 3-player sheet is fiction → IndexError. Python fails loud (JS would return undefined).

2 · Change the sheet

squad.append("Otto")       # add to the END (no push in Python)
squad.remove("Otto")       # remove BY VALUE (no splice by index)
# both return None — side effects, never assign from them

Removing compacts the list: everything after the removed seat slides left. Seat [2] may be a different player after a removal.

3 · Lists are flexible

ages = [23, 28, 31]              # numbers
mixed = ["Otto", 23, True]       # mixing types is allowed
tasks = [                        # multi-line lists — brackets matter, not lines
    "Email my boss",
    "Write a poem for Otto",
]

4 · The AI payoff

Put tasks in a list, hand one to the LLM wrapped in an instruction:

print_llm_response(f"Please complete this task: {tasks[0]}")

A bare tasks[0] as the prompt works, but the wrapper tells the LLM its job. One-off display → print_llm_response. Need to reuse → get_llm_response.

Check yourself

After squad.remove("Isabel"), what is squad[2] (squad was ["Tommy","Isabel","Daniel","Otto"])?

Removal compacts the list. After removing Isabel, two players remain: seats 0 and 1. Seat 2 no longer exists → IndexError.

x = squad.append("Otto") — what does x hold?

Mutators return None. JS push returns the length; Python append deliberately gives you nothing.

Which one reliably tells the LLM its job?

The f-string wrapper is an instruction, so the LLM knows its role. A bare task works but is a weaker prompt.
Forecast: completing all 3 tasks means repeating that line for [0], [1], [2] — the same repetition that started this lesson. Next lesson kills it with a loop that's shorter than forEach.
