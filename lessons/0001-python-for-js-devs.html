Lesson 0001 — Python for JS Devs

Module 1 essentials, framed for a frontend engineer. One win: translate any JS habit into correct Python.

You already know how to program. This lesson is not "learn coding" — it's "learn Python's rulebook". Same sport, different league.

1 · Values and types

str, int, float, bool. Two rule changes from JS:

  • True/False — capital letters. JS lowercase won't parse.
  • No silent coercion. "1" + 1 raises TypeError. JS returns "11". Python fails loud, on purpose.

2 · Variables

snake_case naming, dynamic typing like let, no declaration keywords.

player_name = "Salah"    # str
player_name = 11         # now int — fine, Python doesn't care
2players = 1             # SyntaxError — can't start with a digit
player-name = 1          # actually subtraction, not a name

3 · Strings and f-strings

Triple quotes for multi-line. The f prefix is mandatory:

f"{42.66666:.2f}"        # '42.67'  (2 decimal places)
print("Salah", 11)       # "Salah 11"  (space between args)
print("Salah" + 11)      # TypeError  (no coercion)

4 · Functions

def cheer(team):
    return team + " goalll!"

cheer("Al Ahly")         # returns the string (silent)
print(cheer("Al Ahly"))  # prints it
  • def name(params): + indented body. No braces.
  • No return → returns None (not undefined).
  • return a, b → a tuple (a, b).

Check yourself

What does print("Salah" + 11) do?

No silent coercion in Python. Adding a str and an int is a TypeError.

A function has print(...) inside but no return. It returns…

print() is a side effect. Without return, the function returns None — Python's "nothing".

Which f-string prints 12.34 from n = 12.34567?

The f prefix makes it an f-string; :.2f = 2 decimals. Missing f → braces print literally.
