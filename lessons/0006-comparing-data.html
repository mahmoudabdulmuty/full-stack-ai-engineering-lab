Lesson 0006 — Comparing Data

Module 2, Lesson 5. One win: every comparison returns a True/False you can store, combine, and act on.

The VAR referee's decision is binary: goal or no goal. Python comparisons work the same — every `>`, `<`, `==` evaluates to a boolean you can hold in a variable.

1 · Comparisons are VALUES

vini_age = 26
modric_age = 40
print(vini_age < modric_age)          # True
is_oldest = modric_age > vini_age     # store the comparison
print(type(is_oldest))                # <class 'bool'>

True/False are capitalized (JS lowercase). No === exists — == is all there is.

2 · = vs == — Python protects you

print(vini_age == 26)   # True  — comparison
print(vini_age = 26)    # TypeError! parses as a keyword argument

In JS, assignment is an expression (if (x = 5) silently corrupts). In Python assignment is a statement only — inside a call it becomes keyword-argument syntax and fails loud.

3 · Logic in words

(fitness >= 8) and (not injured)   # JS: &&
(fitness < 5) or injured           # JS: ||
not (fitness == 8)                 # JS: !  — prefer: fitness != 8

No coercion: "5" == 5 → False. Strings compare char-by-char, case-sensitively: "starter" == "Starter" → False.
