Part 1 — Lists & Loops

tasks = ["a", "b", "c"]. After tasks.remove("a"), what is tasks[1]?

Removal compacts the list: "b" moves to seat 0, "c" to seat 1. Positions are recalculated after every mutation.

What does x = [1, 2].append(3) store in x?

append mutates in place and returns None. Chaining or assigning from mutators silently produces None — the bug bites three lines later, not here.

After for t in ["x", "y", "z"]: pass — what is t?

No block scope in Python. The loop variable is an ordinary name that survives the loop holding its final binding.

Part 2 — Dictionaries & Prompts

d = {"a": 1}. Which access returns 1?

Dicts are key-only: square brackets with the literal key. No dot access, no positional index — d[0] is a KeyError, not a position.

profile = {"pages": 200}. Then: line = f"{profile['pages']}", then profile["pages"] = 350. What is line?

f-strings evaluate once, producing a new immutable string. Mutating the dict afterwards changes nothing about text already built. Rebuild the string to see new values.

Part 3 — Comparisons & Decisions

Which expression is True?

"5" + 5 raises TypeError (no arithmetic coercion). "5" == 5 is False (no comparison coercion). not True is False. "5" != 5 is True — they are genuinely different types.

print(x = 5) — what happens?

Assignment is a statement, not an expression. Inside a call, name=value is keyword-argument syntax; print() has no such parameter. JS's silent if (x = 5) bug is impossible here.

In a loop over tasks, where does print(len(later_tasks)) go to run exactly once, after everything?

Indentation is membership. Flush-left code sits outside the loop and runs once when all passes are done — measuring the finished accumulator.

Which function correctly returns the matching player (or None)?

The else-return trapdoor kills the loop on the first non-match — later players are never checked. Match → return immediately; no match → loop finishes, return None as the fallback line.

The Book Tracker finale: loop over tasks (list of dicts with "minutes" and "description"). Tasks with minutes <= 20 go to print_llm_response now; the rest append their description to later_tasks. Print the count afterwards.
