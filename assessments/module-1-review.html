Part A — Quiz

Q1. What does type(3.14) return?

type() reports the class of a value. 3.14 is a float — but put quotes around it, "3.14", and it becomes a string, because the quotes win. Looks like a number, behaves like text.

Q2. Dynamic typing (type your answer, then check)

score = 10
score = "ten goals"
This runs fine in Python. Explain why in one sentence. Then name the one thing JS's let does the same way — and one thing Python refuses to do that JS happily does.
Key points to hit:
  • Python is dynamically typed — a variable's type comes from its current value, not a declaration.
  • JS let does exactly the same.
  • Python refuses silent coercion: "1" + 1 raises a TypeError; JS returns "11".
Python is dynamically typed: a variable's type comes from its current value, not a declaration — exactly like JS let. The difference is coercion: "1" + 1 raises a TypeError in Python (it refuses to guess), while JS silently returns "11". Python fails loud, JS shrugs.

Q3. F-string formatting (write the code, then check)

Write a single f-string that prints the number 42.66666 rounded to 2 decimal places.
Key markers: the string must be an f-string (the f prefix) and it must carry the format specifier .2f inside the braces: f"{42.66666:.2f}".
f"{42.66666:.2f}" → '42.67'. The :.2f after the expression is the format specifier: 2 digits after the decimal point. round(42.66666, 2) also gives 42.67, but :.2f is the display tool inside the string.

Q4. Which of these follows the Python convention for variable names?

player_name — snake_case is the Python convention. Beware the trap: playerName is valid Python (it just looks foreign), 2players is invalid (can't start with a digit), and player-name is actually a subtraction, not a name.

Q5. What actually happens when this runs?

print("Salah", 11)
print("Salah" + 11)
print(a, b) separates arguments with a space — Salah 11. print(a + b) tries to add them, and Python refuses to add a str and an int: TypeError. No silent coercion, ever.

Q6. What do these two len() calls return?

len("stadium")
len([1, 2, 3])
7 characters in "stadium", 3 elements in the list. The generalization: len() counts the items in a container — characters in a string, elements in a list. One function, same job, bigger containers.

Q7. Predict the output — don't run it.

def cheer(team):
    print(team + " goalll!")

result = cheer("Al Ahly")
print(result)
cheer() has no return, so it returns None — the print inside it is a side effect. So result holds None, and the second print shows it. Not undefined — that's JS. Python's "no value" is None.

Q8. def get_team_stats() ends with return "wins", 30. What does a call return?

Multiple values after return get packed into a tuple — Python's immutable ordered collection. It's one object you can unpack or index.

Q9. Imports (type your answer, then check)

When do you reach for from module import func instead of import module? And does Python need an export keyword before a function you want to import?
Key points to hit:
  • import module keeps the namespace → module.func(); good for many functions or avoiding name clashes.
  • from module import func pulls the name in directly → func().
  • No export keyword exists — everything is importable by default.
import module keeps the namespace — you call module.func() — good when you need several functions or want to avoid name clashes. from module import func pulls just that name in so you call func() directly. No export keyword exists: in Python everything is importable by default.

Q10. You need to store the LLM's response and reuse it later. Which helper?

get_llm_response() returns the response as a string — store it and reuse it. print_llm_response() prints to screen and returns None. Rule: need the value → get; just show it → print_llm.

Part B — Working with a Virtual Library (code assignment)

Exercise 1 — Book Information

Create variables for a book's title, author, year_published (int), and copies_available (int). Print one multi-line summary that reads like a library record card using a single f-string (use triple quotes).
This one isn't a JS habit — it's a Python-ism. Write the triple-quoted string without the f prefix and your {variables} print literally instead of being replaced. The f is what activates the interpolation. 
book_title = "The Kite Runner"
book_author = "Khaled Hosseini"
year_published = 2003
copies_available = 5

print(f"""Library record
Title:  {book_title}
Author: {book_author}
Year:   {year_published}
Copies: {copies_available}""")

Exercise 2 — Book Checkout

A reader checks out one copy. The copies number must go down by 1, and you must print a confirmation message that includes the new number. Show the exact line that updates the number.
Python has no ++ operator. The JS habit copies_available++ is a SyntaxError here. Use copies_available = copies_available - 1 or the shorthand copies_available -= 1. 
copies_available = copies_available - 1   # or: copies_available -= 1
print(f"Checked out — {copies_available} copies remain.")

Exercise 3 — Book Request Handling

The library doesn't have the requested book. Print a friendly message telling the reader (a) it's not in our system and (b) which book they asked for — using a variable, no hard-coded text.
If you build the message with + and accidentally add an int variable into it — like the year or copies — Python raises a TypeError (no coercion, remember?). This is exactly the "loud error" from Q5. Use an f-string and the whole trap disappears. 
requested_book = "The Count of Monte Cristo"
print(f"Sorry, {requested_book} is not in our system. Try the reservations desk.")
